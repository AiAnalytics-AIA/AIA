# AIA reference rebuild package

A forensic preservation and clean-room rebuild specification for the original
AIA / NPC Panel prototype.

Its purpose is that the production rebuild can proceed without relying on
undocumented knowledge, memory or guesswork — and that nothing important in the
original system disappears silently.

## To complete the audit

Supply the reference tree or the original ZIP, then:

```bash
# from the production repository root
export AIA_LEGACY_REFERENCE=/path/to/npc-panel-reference

# 1. prove the tree is the snapshot this package refers to
python aia-reference-rebuild-package/tools/verify_reference_inventory.py \
    --reference "$AIA_LEGACY_REFERENCE"

# 2. rebuild the inventory with sizes, line counts and verified hashes
python aia-reference-rebuild-package/tools/build_reference_inventory.py \
    --reference "$AIA_LEGACY_REFERENCE"
```

If check **C10** passes, the tree is bit-identical to the snapshot every
downstream parity claim is anchored to. If it fails, the tree is a different
version and the divergence must be resolved before any analysis is trusted.

The ZIP itself is still wanted even if the tree is supplied, for two fields no
tree can provide: the original ZIP filename and its SHA256, which are the
top-level identity of the delivery.

## What the manifest does and does not cover

The manifest is **canonical-only**. It excludes runtime-generated directories:
`data/`, `logs/`, `runs/`, `prototype_outputs/`, `vystupy/`, `diagnostics/`,
`remediation/`, `full_simulation_runs/`, `full_simulation_benchmarks/`,
`full_simulation_batches/`, caches.

So anything the prototype *produced while running* — generated reports,
simulation run outputs, logs — is outside this snapshot entirely and can only be
recovered from the original ZIP. If any of it is needed as evidence of
behaviour, the ZIP is not optional.

The good news, established here: the large population assets are **not** in the
excluded set. Three generations of the full panel and 18 special panels are
canonical, hashed entries. See `data-asset-ledger.md`.

## Principles this package holds to

1. **The reference is immutable.** Nothing here modifies, refactors, renames or
   "cleans up" the prototype. All analysis lives outside it.
2. **Evidence mode is always declared.** Every artifact records whether it was
   built from the tree or from the manifest alone. A manifest-mode artifact is
   never to be read as a content audit.
3. **Absence is reported, not filled in.** A gap is recorded as a gap. The
   failure mode this package exists to prevent is an authoritative-looking
   document containing invented specifics.
4. **The inventory is capability-based, not filename-based** — once contents are
   available. One prototype module may implement persistence, rules, UI and model
   calls at once, and must be decomposed by responsibility, not filed under one
   label.
