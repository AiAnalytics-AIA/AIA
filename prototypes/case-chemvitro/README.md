# Případová studie ChemVitro: one case, three studies

Version 1, 4 Nov 2026, by Aram Bahbouh. The second shared case, after Velis. Each author writes three study types on
the same fictional case, so the executive can compare the types and the authors. Where Velis is an e-shop choosing a
logistics set-up, ChemVitro is a chemical company choosing where in Czechia, Germany or Poland to build its own plant.

**Everything here is fictional.** ChemVitro a.s., its sites, towns, parks, utilities, authorities, suppliers, people and
numbers are invented; only the regions are real. The data is generated by code from a fixed seed. It is design material:
nothing in `apps/` imports it.

| File | What |
|---|---|
| [`CASE.md`](CASE.md) | **Start here.** The company, the situation, the decision, the options, the constraints, the rule, the people, the client's answers, every file, and what to research |
| [`STUDIES.md`](STUDIES.md) | The three study types (situation report, cost model, cost model + workers), the parts every report shares, and the executive's feedback sheet |
| [`ANSWER-KEY.md`](ANSWER-KEY.md) | What was planted in the data and the documents, and the reference result. Open it only after your reports are finished |
| [`data/`](data/) | The client's eleven data files (XLSX and CSV, `;`-separated, UTF-8), and the survey's questionnaire (`pruzkum_pracovniku_2026_dotaznik.md`) |
| [`documents/`](documents/) | The client's seven documents as PDF (35 pages), and their HTML sources in `documents/html/` |
| [`tools/`](tools/) | `params.py` holds every parameter; `generate.py` writes `data/`, `documents.py` writes `documents/`, `reference.py` computes the answer key's reference result |

## How to use it

1. Read `CASE.md`, then the study type you're writing in `STUDIES.md`.
2. Work only from this folder, plus public sources for Rešerše. When the client has an answer, it is in CASE.md §8.
3. Write the report in Czech, named as STUDIES.md suggests.
4. When all reports exist, compare them with `ANSWER-KEY.md` and run the executive's sheet.

**Don't open `tools/`** before your reports are written either: `params.py` and `reference.py` contain what is planted.

**For Nigel's Claude.** `git pull` the `develop` branch of AiAnalytics-AIA/AIA, then read
`prototypes/case-chemvitro/README.md`, `CASE.md` and `STUDIES.md` in full before starting a study. Don't open `ANSWER-KEY.md`
or `tools/` until the report is written.

## Regenerating

From the repo root, with a Python that has numpy and openpyxl, and Google Chrome or Chromium for the PDFs (set `CHROME` to
its path if it is not the macOS default):

```bash
python3 prototypes/case-chemvitro/tools/generate.py     # data/, byte-identical on every run
```

```bash
python3 prototypes/case-chemvitro/tools/documents.py    # documents/; the PDFs differ only in Chrome's creation date
```

```bash
python3 prototypes/case-chemvitro/tools/reference.py    # tools/answer_key_reference.json (seed 20270201)
```

## Known gaps

- The public figures (carbon price, limits, fees, wages, tax) are deliberately not in the pack. Each study researches and
  cites them, so the authors' Rešerše can be compared too.
- The survey is fictional respondents recruited by a fictional agency. A real survey, or AIA's AI respondents, would give
  different answers. All authors use this file so their reports stay comparable.
