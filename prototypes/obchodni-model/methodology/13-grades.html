Chapter 12

Grades, sources and the release gate

Every number in a type-2 report carries a grade in small type and a numbered source at the end of its chapter. The grade says how the number came to be; the source says where. Behind the one printed grade stand four attributes.

The four attributes behind a grade

Version 2 of this methodology, following the review's I3, split a number's label into four attributes. The printed grade is a projection of them; the outline and the screens hold all four (boards MV4 and M6; the other boards' chips still show one grade, README "Known wrong").

In the code the print grades are five today, PrintGrade in domain/report/evidence.py: measured, calibrated, modelled, holdout-pending, unknown, strongest first, a claim printing the weakest grade of the fields behind it, a missing grade printing "?". The plan adds CALCULATED (výpočet) and ESTIMATED (odhad) with the register's status (cost-model-study#CP8, #CP10), and ADR 0027 the client-reported origin. The scope's cost-model-study#CP8b (new) maps all seven in one table with an admission rule each: z dat klienta = CLIENT_REPORTED, výpočet = CALCULATED, odhad = ESTIMATED, úsudek = a labelled judgement with its author, veřejný zdroj, právní předpis (legal-context#LGL5), průzkum = the survey origins. The provisional state is deep-research-v2#DRV1's. The weakest-grade rule carries over: a number computed from a judgement input prints výpočet but its sensitivity to that input is shown; a number from the futures prints odhad whatever its inputs.

Sources, numbered per chapter

  • Each chapter ends with Zdroje a stupně: a numbered list; each printed number cites a list entry by its number (R2-P02: "z dat klienta 1").
  • An entry names the document by its cited name and page or paragraph ("Zápis zadání s klientem §6", "Dopis dodavatele, s. 1"), the file for data, the table for a computed value ("výpočet: tabulka T5 v příloze"), or the method's status for an estimate ("odhad (metoda čeká na schválení metodikem)").
  • An entry may carry two grades when a number rests on both ("výpočet; z dat klienta: Srovnatelné závody"); the weaker is printed at the number.
  • The document register (Appendix A) maps every cited name to its file, so a source is checkable with one open.
  • In AIA, the section-source manifest (domain/report/sources.py) already records each section's sources by artefact id and SHA-256; the numbered list is its printed form.

The provisional state

Prozatímní is a validation status, not a grade. It marks a public input not yet verified at the source, and it is printed in three places: the input table's state column (T9), the sentence that uses the input ("dlouhodobý vývoj cen energie (prozatímní údaj)"), and the first-page state box with the count (16 of 54). It is removed only by a dated verification by a named person. The report's running head carries it while any decisive input is provisional: the exemplar prints Pracovní verze · prozatímní on every page.

The release gate (R9, proposed)

Waits for the owner. R9 changes two earlier decisions: W27 (an estimate whose method is not registered still reaches the client report, labelled, with a warning, never refused) and report-delivery RD0 of 22 October ("warnings for all of it"). Boards MV0 (M-5), MV5 (§ 04) and M6 show it as proposed.

As proposed, for a business-decision report:

  • Every decision-critical claim is checked twice: support in its source (code) and correct interpretation (a person who is not the claim's author).
  • A recommendation that rests on a method outside the register is předběžné doporučení and is never released as approved investment advice. The exemplar's recommendation rests on the futures, so it is provisional in this sense, and its summary would say so under R9.
  • Exploratory material enters the report only with explicit limits ("exploratory; does not support the recommendation"). The weighting-scenario map is such material.
  • Approval records the exact version and the unresolved qualifications; "approved" means ready in substance, not merely checked.
  • The Deep Research thresholds of M-7 (citation precision ≥ 90 %, unsupported claims < 10 %) are one check, not the release criterion.

What exists today: approval once per stored version with the approver and self-approval rules recorded (application/report_approval.py); the client gate's checks as warnings recorded on the approval's ledger row (domain/report/client_gate.py, RD0); the sentence check (RD7). What R9 adds: the recommendation's status as a field of the approval, the qualifications list, and the second, human reading of each decision-critical claim.
